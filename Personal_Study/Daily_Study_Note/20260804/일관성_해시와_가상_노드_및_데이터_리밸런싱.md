# 일관성 해시와 가상 노드 및 데이터 리밸런싱

> 2026-08-04 신규 주제 · 확장 대상: 자료구조&알고리즘

## 학습 목표

- 모듈로 해시 분산의 리밸런싱 폭발 문제를 정량적으로 설명한다
- 일관성 해시 링에서 키·노드 매핑과 노드 추가/삭제 시 이동 범위를 계산한다
- 가상 노드로 부하 불균형과 표준편차를 줄이는 원리를 이해한다
- 바운디드 로드·랑데부 해시 등 변형 기법의 trade-off 를 비교한다

## 1. 모듈로 해시의 함정 — 노드 하나 늘리면 전부 이동

분산 캐시나 샤딩에서 키를 노드에 배정하는 가장 단순한 방법은 `hash(key) % N` 이다. N 이 고정이면 완벽하게 균등하다. 문제는 N 이 바뀌는 순간이다. 노드를 하나 추가해 N 이 4→5 가 되면, 거의 **모든 키의 배정이 달라진다**.

```python
def modulo_assign(key, num_nodes):
    return hash(key) % num_nodes

# N=4 에서 N=5 로 바뀌면 재배치되는 키 비율 측정
import hashlib
def h(k):
    return int(hashlib.md5(str(k).encode()).hexdigest(), 16)

keys = range(100_000)
before = {k: h(k) % 4 for k in keys}
after  = {k: h(k) % 5 for k in keys}
moved = sum(1 for k in keys if before[k] != after[k])
print(f"{moved / len(keys):.1%} 재배치")   # 약 80% 이동
```

N 이 하나 늘었을 뿐인데 약 80% 의 키가 다른 노드로 옮겨간다. 캐시라면 대량 캐시 미스로 뒤편 DB 에 트래픽이 폭발하고(cache stampede), 샤드 DB 라면 거대한 데이터 마이그레이션이 발생한다. 이론적으로 이상적인 재배치 비율은 `1/N`(추가된 노드가 흡수해야 할 몫)뿐인데, 모듈로는 그 훨씬 위를 이동시킨다.

## 2. 일관성 해시 — 링 위에 키와 노드를 함께 놓다

일관성 해시(consistent hashing)는 해시 값의 공간을 **원형 링**으로 본다(예: 0 ~ 2³²−1 이 원을 이룸). 노드와 키를 같은 해시 함수로 링 위의 점에 매핑한다. 키는 링을 **시계 방향으로 돌아 처음 만나는 노드**에 배정된다.

```python
import bisect, hashlib

class ConsistentHash:
    def __init__(self):
        self.ring = []          # 정렬된 해시 값 리스트
        self.node_of = {}       # 해시 -> 노드 이름

    def _h(self, s):
        return int(hashlib.md5(str(s).encode()).hexdigest(), 16) % (2**32)

    def add_node(self, node):
        pos = self._h(node)
        bisect.insort(self.ring, pos)
        self.node_of[pos] = node

    def get_node(self, key):
        if not self.ring:
            return None
        pos = self._h(key)
        idx = bisect.bisect_right(self.ring, pos) % len(self.ring)
        return self.node_of[self.ring[idx]]
```

핵심은 노드가 추가/삭제될 때 **영향받는 키가 링 위 인접 구간에 국한**된다는 점이다. 노드 D 를 추가하면, 링에서 D 바로 앞 구간에 있던 키들만 D 로 옮겨가고 나머지는 그대로다. 이론적으로 노드 추가 시 이동하는 키는 평균 `1/(N+1)` 에 불과하다. 모듈로의 80% 와 대비된다.

## 3. 노드 삭제와 복구 — 인접 노드가 흡수

노드가 죽으면 그 노드가 담당하던 링 구간의 키들은 시계 방향 **다음 노드**로 자동 이관된다. 다른 구간의 키는 전혀 영향받지 않는다. 이것이 일관성 해시가 분산 캐시(memcached 클라이언트, Redis Cluster 의 개념적 기반)와 DHT(Dynamo, Cassandra)에서 표준이 된 이유다.

```python
ch = ConsistentHash()
for n in ["A", "B", "C"]:
    ch.add_node(n)

# C 가 죽기 전후로 키 배정이 어떻게 바뀌는지
before = {k: ch.get_node(k) for k in range(10000)}
# C 제거
pos_c = ch._h("C")
ch.ring.remove(pos_c); del ch.node_of[pos_c]
after = {k: ch.get_node(k) for k in range(10000)}

moved = sum(1 for k in range(10000) if before[k] != after[k])
print(f"C 제거 시 {moved/10000:.1%} 만 이동")   # C 담당분(약 1/3)만 이동
```

C 를 제거하면 C 가 담당하던 약 1/3 의 키만 인접 노드로 옮겨가고, A·B 사이의 키는 그대로 유지된다. 이 국소성이 리밸런싱 비용을 극적으로 줄인다.

## 4. 가상 노드 — 부하 불균형을 잡는 결정적 기법

기본 일관성 해시에는 결함이 있다. 노드가 링 위에 무작위로 흩어지면 구간 크기가 들쭉날쭉해 노드마다 담당 키 수가 크게 차이 난다. 노드가 적을수록 이 불균형이 심하다. 노드 3개면 어떤 노드는 링의 절반을, 다른 노드는 10% 만 맡는 상황이 흔하다.

**가상 노드(virtual node)** 가 해법이다. 물리 노드 하나를 링 위 여러 점(예: 150개)에 복제해 배치한다. 각 물리 노드가 링 곳곳에 흩어진 수많은 작은 구간을 담당하게 되어, 큰 수의 법칙에 의해 부하가 고르게 평준화된다.

```python
class HashRingVNodes:
    def __init__(self, vnodes=150):
        self.vnodes = vnodes
        self.ring = []
        self.node_of = {}

    def _h(self, s):
        return int(hashlib.md5(str(s).encode()).hexdigest(), 16) % (2**32)

    def add_node(self, node):
        for i in range(self.vnodes):
            pos = self._h(f"{node}#{i}")     # 노드마다 vnodes 개 점
            bisect.insort(self.ring, pos)
            self.node_of[pos] = node

    def get_node(self, key):
        idx = bisect.bisect_right(self.ring, self._h(key)) % len(self.ring)
        return self.node_of[self.ring[idx]]
```

가상 노드 수를 늘리면 부하 분산의 표준편차가 줄어든다. 실측하면 vnode=1 일 때 노드 간 부하 편차가 ±40% 를 넘다가, vnode=150 이면 ±5% 이내로 수렴한다. 다만 vnode 수만큼 링 자료구조가 커져 조회 시 이진 탐색 비용과 메모리가 는다. 100~200 이 실무의 관례적 균형점이다.

```python
# 부하 표준편차로 vnode 효과 측정
from collections import Counter
for v in (1, 10, 150):
    ring = HashRingVNodes(vnodes=v)
    for n in ["A", "B", "C", "D", "E"]:
        ring.add_node(n)
    load = Counter(ring.get_node(k) for k in range(100_000))
    vals = list(load.values())
    mean = sum(vals) / len(vals)
    std = (sum((x - mean) ** 2 for x in vals) / len(vals)) ** 0.5
    print(f"vnode={v:>3}: 표준편차 {std/mean:.1%}")
```

## 5. 가중치와 이질적 노드

가상 노드는 **이질적 하드웨어**를 자연스럽게 지원한다. 용량이 큰 노드에 더 많은 가상 노드를 부여하면, 그 노드가 링의 더 넓은 몫을 담당해 비례적으로 많은 부하를 받는다. CPU·메모리가 2배인 노드에 vnode 를 2배 주면 트래픽도 대략 2배로 흘러간다. 물리 노드마다 균일한 가상 노드 수를 강제하지 않아도 되는 유연성이 실무에서 특히 유용하다.

## 6. 변형 기법 — 랑데부 해시와 바운디드 로드

**랑데부 해시(rendezvous / HRW, Highest Random Weight)** 는 링 없이 같은 목표를 달성한다. 각 키에 대해 모든 노드와의 `hash(key, node)` 를 계산하고 **가장 높은 값의 노드**를 고른다.

```python
def rendezvous(key, nodes):
    return max(nodes, key=lambda n: h(f"{key}:{n}"))
```

노드 목록만 있으면 되어 구현이 단순하고, 노드 추가/삭제 시 이동 비율도 최소(`1/N`)다. 단점은 조회가 O(N)(노드 수만큼 해시 계산)이라 노드가 많으면 링 기반보다 느리다. 노드 수가 수십 개 이하일 때 매력적이다.

**바운디드 로드 일관성 해시(consistent hashing with bounded loads)** 는 일관성 해시의 부하 편차를 상한으로 강제한다. 각 노드에 `(1+ε) × 평균부하` 라는 용량 한계를 두고, 시계 방향으로 돌다 만난 노드가 이미 한계면 다음 노드로 넘긴다. 핫키로 특정 노드가 과부하되는 것을 막는다. Google 이 자사 로드밸런서에 적용해 발표한 기법으로, 캐시 서버 앞단에서 특히 유용하다.

## 7. 실무 적용 지점

일관성 해시는 여러 시스템의 뼈대다. Amazon Dynamo·Cassandra 는 가상 노드 기반 일관성 해시로 파티션을 분산하고 복제본을 링의 다음 N개 노드에 둔다. memcached 클라이언트(ketama)는 서버 목록을 링으로 만들어 서버 증감 시 캐시 이동을 최소화한다. Redis Cluster 는 16384 개의 해시 슬롯을 노드에 분배하는데, 이는 순수 링 대신 슬롯을 명시적으로 노드에 매핑하는 변형이지만 "키 재배치 최소화"라는 동일한 목표를 공유한다.

```python
# Redis Cluster 슬롯 계산 방식 (개념)
def redis_slot(key):
    # {} 해시태그가 있으면 그 안만 해싱 (멀티키 연산 co-location)
    return crc16(key) % 16384
```

Redis 가 링 대신 고정 슬롯 수를 쓰는 이유는, 슬롯 단위로 노드 간 이동을 명시적으로 제어(리샤딩)하기 위해서다. 링의 자동성 대신 운영자가 "어느 슬롯을 어디로 옮길지" 통제한다.

## 8. 점프 일관성 해시 — 메모리 없는 대안

구글이 발표한 **점프 일관성 해시(jump consistent hash)** 는 링 자료구조도 가상 노드 테이블도 없이, 오직 산술만으로 키를 버킷에 배정한다. 메모리 사용이 O(1)이고 계산이 매우 빠르다. 노드 수가 N 일 때 키가 어느 버킷(0 ~ N−1)에 가는지 몇 줄의 루프로 결정한다.

```python
def jump_hash(key: int, num_buckets: int) -> int:
    b, j = -1, 0
    while j < num_buckets:
        b = j
        key = (key * 2862933555777941757 + 1) & 0xFFFFFFFFFFFFFFFF
        j = int((b + 1) * (2**31 / ((key >> 33) + 1)))
    return b
```

버킷 수가 N→N+1 로 늘 때 정확히 `1/(N+1)` 의 키만 새 버킷으로 이동하며, 부하는 완벽히 균등하다. 링 기반보다 분산 품질이 좋고 메모리도 안 쓴다. 대신 **버킷은 0..N−1 로 번호가 매겨진 순차 슬롯**이라는 제약이 있다. 임의의 노드를 중간에서 제거하고 나머지 번호를 유지할 수 없다. 노드 목록이 끝에서만 늘거나 주는(append-only) 샤드 개수 스케일링에는 이상적이지만, 특정 노드가 죽고 그 자리만 대체되는 상황에는 부적합하다.

이 제약 때문에 점프 해시는 "샤드 수를 늘리는" 데이터베이스 샤딩이나 스토리지 확장에 쓰이고, "임의 노드가 수시로 죽고 살아나는" 캐시 클러스터에는 링 + 가상 노드가 더 적합하다. 두 기법은 경쟁이 아니라 서로 다른 운영 모델에 대응한다.

## 9. trade-off 정리

일관성 해시는 노드 증감 시 이동을 `1/N` 수준으로 억제하는 대가로, 부하 균등성을 완벽히 보장하지 못한다. 가상 노드로 균등성을 얻지만 링 크기와 조회 비용, 메모리가 는다. 랑데부 해시는 구현이 단순하고 이동이 최소지만 조회가 O(N)이라 대규모 노드에 부적합하다. 바운디드 로드는 핫키 과부하를 막지만, 용량 초과 시 키가 원래 노드가 아닌 곳으로 밀려 지역성(locality)이 약간 손상된다. 캐시냐 영속 스토리지냐, 노드 수가 수십인지 수천인지, 핫키가 존재하는지에 따라 기법을 선택한다. 대부분의 분산 캐시·DHT 는 "가상 노드 + 일관성 해시"를 기본값으로 삼는 것이 검증된 출발점이다.
